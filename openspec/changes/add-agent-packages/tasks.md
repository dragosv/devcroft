Record per-platform URLs, digests, component versions, libc and loader, dependencies, required commands, relative `state_paths`, Linux `procfs` need, macOS `HTTPS_PROXY` userinfo (`http://nono:<token>@127.0.0.1:<port>`) behavior across startup and model requests, and any update or extra-download behavior. ## 2. Install and select

- [ ] 2.1 Implement validated embedded and user recipes: names, relative `state_paths`, `argv[0]` inside the object before download and after extraction, Linux libc, and `agents/` beside the resolved user configuration (`XDG_CONFIG_HOME`). Add a committed seed pinning every registry revision and a dev-only generator that reproduces it. Implement `single-binary` and `archive` layouts with checksums, sanitized entries, fetch and extraction limits, and atomic publication. Run validation, checksum, digest, pin and archive-escape tests as unit tests that do not skip when no provider is available.
- [ ] 2.2 Add the embedded recipes to `Cargo.toml`’s anchored `include`, and make every crate the fetcher and extractor call a direct dependency. Build from the unpacked `cargo package` output and confirm `agent list` shows the recipes. Regenerate attribution if `Cargo.lock` changes.
- [ ] 2.3 Implement host `agent list`, `agent install <recipe> [--version <v>]` and `agent uninstall <recipe> [--version <v>]`, object-specific pins, and the lease-until-referenced rule on `up`, `agent install` and `agent run`. Move `rm`’s `Meta` read and state removal under the lifecycle lock and its sweep under the store lease. Test mismatches, unsafe entries, a stalled server, an expansion bomb, install concurrent with `rm`, `rm` concurrent with `up`, two sandboxes sharing an object, and two different objects with the same recipe name and version.
- [ ] 2.4 Implement user selection, deterministic `auth` mode precedence, flags, the canonical `recipe_digest` and `object_id` serializations with golden vectors, and staleness across non-binary recipe changes such as `hosts`, `launch.env` or `reserved_env`. Implement `mode1_recipes` retention across `--no-agent` and recipe switches, the retained-state line, and `cd <project_root> && up [--name <n>]` remedy formatting. Test legacy, stopped and named sandboxes, opt-out across recreation, switching recipe and version, and restart after the recorded recipe disappears from the release.
- [ ] 2.5 Insert recipe checks and downloads at the boundary from `validate-before-recreate`. Confirm failed preparation leaves the previous sandbox available. Check brokers, the proxy decision and recipe hosts against the manifest’s network policy plus the recipe’s hosts before provider resolution, and check the agent’s executable against its own grants. Verify that `policy --render`, `why` and compilation use one final policy, with origin labels, baseline denials and an unchanged provider fingerprint and capture.
