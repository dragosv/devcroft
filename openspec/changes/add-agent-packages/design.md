## Scope and release evidence

Start with OpenCode for one explicitly named model provider, qualifying `linux-aarch64` and `macos-arm64` independently. On each platform record the exact executable, checksum, library dependencies, relative `state_paths` under `HOME`, self-update settings, required commands, Linux `procfs` need, macOS `HTTPS_PROXY` userinfo (`http://nono:<token>@127.0.0.1:<port>`) compatibility across startup and model requests (since Bun previously misparsed `<token>@127.0.0.1` in `docs/agents.md`), and a successful request through devcroft’s broker. Qualify Goose by the same criteria on any platform where OpenCode fails, or publish only the passing platform(s). Advertise only combinations that pass; a catalog entry or a successful download alone cannot establish support.

## Install and retain a package

Keep reviewed URLs and checksums in embedded versioned recipes. A committed seed pins upstream coordinates and tags; the development-only generator can run from a clean checkout. The installed CLI fetches directly over HTTPS and verifies the payload without invoking a host package manager. Ship the `single-binary` and safe `archive` layouts here; refuse unimplemented layouts at layer `config` before download. Validate user recipes with the same rules and label their provenance.

Use the shared artifact store with per-object locks, atomic publication and read-only sandbox grants. Hold the agents store lease through the metadata write for every project provider. Explicit installation (`agent install <recipe> [--version <v>]`) pins the object by `object_id`, including when a user recipe overrides the same name and version. Removal sweeps only objects referenced by neither a pin nor any recorded sandbox.

## Project commands and agent state

Start the agent by absolute path through the existing keeper. Leave project tools first on PATH, then user tools, the sandbox’s read-only agent launcher and the base runtime. The launcher applies per-agent environment changes on every invocation. Check its interpreter path and length before teardown. Strip reserved variables after the activation overlay and spawn environment; refuse reserved manifest variables and keepers without this protocol support. Check executable headers against the effective grants.

Store history and configuration in the sandbox HOME. Traverse managed directories via `O_NOFOLLOW` directory descriptors and commit via exclusive temp file plus `renameat` (`OwnedDir`) for host-managed files in workspace-writable directories. Preserve unrelated settings across restarts and recreation. The agent shares this HOME, policy and credential route with project processes. Persist `mode1_recipes` (every recipe name and its relative `state_paths` ever run in shared mode on this sandbox) in `Meta` across `down`, `up`, `up --recreate`, `--no-agent` and recipe switches until `rm`, so a later shared-to-isolated migration can quarantine prior state.

## Selection and startup

Record the selected recipe, requested version, resolved recipe, auth mode, source, protocol version, `object_id`, `recipe_digest` (SHA-256 over the full canonical resolved recipe — artifacts, entrypoints, `launch.env`, `reserved_env`, `hosts`, `hooks`, `requires`, `state_paths` — plus active `auth_mode`) and `mode1_recipes`. Staleness compares `recipe_digest` against re-resolving the recorded selection (never `[agent]` default drift). Preserve recorded selections and explicit opt-outs across plain starts and recreation. A sandbox with no recorded choice adopts the global default only on recreation. A change of selection on any existing sandbox requires recreation. Resolve target recipe `R`'s version and auth deterministically (`--agent-auth`, else `Meta`'s mode only when `Meta` already records `R` without `--agent-from-config`, else `[agent] auth` when `[agent]` names `R`, else `R`'s default — never inherited from a different recipe).

For `agent run [<recipe>]`, an explicit `--sandbox <name>` selects its recorded root or matching manifest; otherwise compare the nearest manifest and the deepest recorded root containing the canonical working directory and choose the deeper root, reporting equal-root ambiguity with the names and `--sandbox`. When no `Meta` exists yet, `<recipe>` on the CLI passes `--agent <recipe>` to `up` (overriding an absent or different `[agent]` default); if neither `<recipe>` nor `[agent]` selects a recipe, fail at layer `config` before starting `up` or downloading. Format every remedy with `cd <quoted project_root> && ` whenever canonical `cwd`'s nearest manifest root differs from `project_root`, and use `up --name <n>` whenever `sandbox_name != manifest.sandbox.name`.

Validate credentials, platform, launch path and selection, then materialize the package before teardown under the lifecycle lock. An already healthy unchanged sandbox uses the recorded choice. A failed replacement download leaves the old keeper and selection in place.

## Authentication and terminal acceptance

The first maintained recipe uses a brokered API key from a non-empty host environment variable. Reject conflicting variable or host declarations, compose the recipe hosts before checking the broker, and show all added grants with their origins. Use the same composed policy for enforcement and inspection. Require an explicit manifest setting for any needed unrestricted loopback and check private procfs only on applicable Linux targets.

Measure a real edit and test using the project’s tools. Use distinct project and agent runtimes in a fixture to make toolchain mix-ups observable. On `agent run` reuse the [terminal transport fixtures](../support-osc7501-terminal/design.md) (`T01`–`T10`, `T12`). During the live project task, observe `hc ls` if the qualified harness natively emits OSC 7501, and otherwise verify devcroft fabricates no reply, identity or state (`OSC-05`) and record `osc7501_native = false` in `docs/agents.md` (`S9`).
